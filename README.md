# figlab · 本地科研绘图平台

把仪器导出的数据变成投稿级矢量图，并允许在图上直接查看与修改数据。
Python 实现，前端为本地网页，五层之间以文件为契约，**不引入数据库、不联网、不需要 Node**。

## 快速开始（拿到就能跑）

Windows 组员先安装 Python 3.10 或以上版本，解压到普通可写目录，双击 `Start-FigLab.cmd`。
首次启动需要联网安装依赖，随后会自动打开 FigLab。使用期间保留启动窗口。Mac 和 Linux 可按下方命令启动。

顶栏「文件位置」显示当前项目、数据、内部输出和单图成品目录。顶栏可切换浅色和深色，设置会在单图和组图间同步。
编辑时保存工作数据和图规格，默认由「导出到桌面并核验」生成成品。需要后台生成内部预览时，可开启导出面板的「编辑后自动生成核验预览」。
归入实验文件夹的单图成品按该实验归档。相同目录里同名的成品会更新现有文件。每张图的具体路径在右侧导出面板显示。
Windows 上「复制矢量图」会把 SVG 和可粘贴到资源管理器的 SVG 文件放入系统剪贴板，也可以直接点「下载 SVG」。
用 Illustrator 打开 SVG 可继续编辑原图中的文字。Photoshop 可通过 Illustrator 的「粘贴为图层」导入兼容的文字和形状。
同时使用不同项目副本时，请用不同端口，并可用环境变量 `FIGLAB_EXPORT_DIR` 为启动的副本设定独立的单图成品目录。

新建单图默认使用 9.708 × 6 cm 的黄金比例画布，配合加粗的 Arial 轴标题、常规字重的刻度和较清晰的线与点。
曲线面板里的「参考」可降低该曲线的视觉权重。对 MS 图，获得有效拟合区间后可突出区间内的实测点和拟合线，保留并淡化区间两侧的点。
已有图继续读取各自保存的规格。

### 在项目里做组图

1. 顶部「组图」可打开或新建组图。已有单图和组图也可从左侧项目树切换。
2. 在单图窗口点「复制图片」，到组图窗口点「粘贴图片」，也可按 Ctrl+V。连续复制多张后可一次粘贴。还可从组图添加项目图、PNG/JPEG/WebP 照片或占位面板。可拖动面板、拖右下角缩放，或点「均匀排列」。
3. 双击曲线面板回到原图。修改原图后，回到组图就会刷新，面板位置和大小沿用当前布局。
4. 点「保存组图」保存在项目中。交接可编辑项目时，把 `figures.json`、`specs/` 和引用的数据集一起迁移。照片随组图规格保存。
5. 点「导出 SVG」得到组图成品，曲线和文字保留为矢量内容。需要 PDF 时，点「打印 / 存为 PDF」，在浏览器中选择保存为 PDF。

项目树可用「实验日期 · 样品或实验简称」命名文件夹，一次实验的不同谱型放入同一文件夹。
图名可写「样品 · 条件或图用途」，类型列会显示 MS、UV–Vis、Tauc 等。搜索框可同时输入样品和谱型筛选。

组内负责人可在启动进程的环境中配置 `OPENAI_API_KEY` 和 `FIGLAB_AI_MODEL`（支持流式 Chat Completions 的模型）。
配置后，组员直接在组图窗口描述布局。每收到一条完整操作，画布就更新一次，可以取消或应用预览。
发送给模型的是指令、面板标题、画布大小和布局坐标。图片和实验数据留在本机。手动操作可离线使用。

### 命令行启动

```bash
# 0) 克隆（或直接下载 zip 解压）
git clone https://github.com/dexiangli/figlab.git
cd figlab

# 1) 装依赖（Python 3.10+，建议 3.12）
pip install -r requirements.txt

# 2) 启动
python run.py 8778

# 3) 浏览器打开 http://127.0.0.1:8778
```

- **零配置**：不需要数据库、不需要联网、不需要 Node（Node 只用于跑开发期 UI 测试）。
- **数据在哪**：`datasets\` 自带一份示例阻抗数据；打开页面即看到两张示例图。
- **导出去哪**：手动「导出到桌面并核验」→ `桌面\FigLab\<图名>\`（pdf/pptx/figlab）；
  停手 1.2 秒的自动导出只写项目内 `outputs\`，不进桌面。
- **新数据一条命令**（推荐入口，也是 AI 接手时的默认做法）：
  ```bash
  python scripts/new_figure.py "D:/数据/20261201阻抗" --kind eis
  ```
  自动做「进站 → 建图 → 导出 PDF」，数据集 ID 从路径里的 8 位日期推成 `eis_20261201`；
  加 `--dry-run` 只看计划不动盘，`--no-export` 只建图。
- **换台机器**：整个文件夹拷走即可。规格文件里的路径一律存成**相对项目根**的写法
  （如 `datasets/eis_20261107/working.csv`），换盘符、换电脑、换用户名都能直接跑；
  只有「桌面成品文件夹」和你手填的目标 PPT 路径是绝对路径——它们本来就在项目之外，
  桌面找不到时自动退回 `~/Desktop`。
- **首次上手**：页面顶栏「?」按钮（或按 `?` 键）有完整的操作说明与快捷键。

```
├─ datasets\<数据集ID>\        每集固定三块
│  ├─ raw\sources\             源文件字节副本（写入后只读）
│  ├─ raw\raw_long.csv         长表快照
│  ├─ raw\raw_meta.json        哈希 / 点数 / 采集时间 / 全部表头参数 / 跳过文件
│  ├─ working.csv              唯一绘图输入（允许人工编辑）
│  └─ ledger.json              摄取 / 修改 / 排除 / 导出 + 理由
├─ history\<数据集ID>.json     撤销/重做历史帧（最多 60 帧，重启不丢）
├─ tasks\requests.jsonl        需求单流水（一行一条，含状态与 AI 回复）
├─ specs\<图ID>.json           每张图一份规格（含对预设的覆盖项）
├─ outputs\<图ID>\             pdf / eps / svg / png + geometry.json + points.json
│                              + export_report.json + verify_report.json
└─ tests\layer*.py             每层一份真实数据跑通脚本

桌面\FigLab\                     成品交付（只有亲手点「导出到桌面并核验」才写）
├─ <数据日期><类别>作图\          一张图一个文件夹；日期取数据自身的，定完不改
│  ├─ <图名>.pdf                 成品（勾选后还有 eps / svg / png）
│  ├─ <图名>.pptx                一键生成的幻灯片（图带回链，可点回平台）
│  └─ <图名>.figlab              项目文件，打开就能接着改
└─ _旧归档\                      上一版按「导出日期」分级的旧产物（只读留存）
```

报告 json 与 CSV 不上桌面，留在 `outputs/<图ID>/`，界面上的「本图输出目录」可直接打开。

**层间契约（文件）**：`raw_meta.json`（摄取→比对/验收）→ `working.csv`（人/交互层→处理/渲染/比对）
→ `ledger.json`（写操作→验收）→ `outputs/<图>/geometry.json`（处理层→渲染/核验）
→ `specs/<图>.json`（规格层→渲染/核验）→ `points.json`（渲染层→交互/核验）
→ `verify_report.json`（核验层→交付）。成品交付是**纯下游副本**，不参与任何层间契约。

## 二、启动命令

Python 3.10+ 均可（本机曾用 3.12 开发）。装好依赖后：

```
cd <项目根>
python run.py 8778
```

浏览器打开 <http://127.0.0.1:8778>。服务**只监听 127.0.0.1**，不做鉴权。
启动前会探测端口：若 8778 被占，直接报错退出，避免「新进程绑定失败、旧进程继续应答」。
组内共享采用每人本地各跑一份、通过共享目录交换 `datasets/` 与 `specs/`，**不得把端口暴露到局域网**。

逐层跑通与验收：

```
python tests\layer1_data.py      # 数据层
%PY% tests\layer2_spec.py      # 处理层 + 规格层
%PY% tests\layer3_render.py    # 渲染层（重新导出）
%PY% tests\layer4_web.py       # 交互层（真实 HTTP）
%PY% tests\layer5_verify.py    # 核验层
%PY% tests\layer7_files.py     # 桌面归档 + 原始/处理后双视图（隔离数据集，不碰真实数据）
%PY% tests\layer8_project.py   # 项目管理器 + 一键出 PPT + 需求单（临时规格与临时归档）
%PY% tests\acceptance.py       # 交付逐条验收
```

> `layer4_web.py` 会**写真实数据集**（排除/改值再恢复），你正在网页上编辑时不要跑它。
> `layer6`、`layer7`、`layer8` 都只在临时数据集 <code>_selftest6</code> / <code>_selftest</code>
> / <code>_selftest8</code> 上写，归档也写到仓库内 <code>tmp_test_archive*\</code>，跑完自动删除；
> 真实数据的四类比对在测试前后必须一致。

## 三、改数据的入口

按 Origin 的操作习惯做了四条路，全部走同一个事务层（一次提交 = 一次校验 + 一次写盘
+ 一条台账 + 一帧历史），任何一处不合格整批回滚：

1. **数据表**：像 Excel 一样选、像 Origin 一样改。
   - 单击选中、按住刷选整块、Shift 连选、Ctrl 挑着选（详见 10.2）；
   - **选中后按 Delete 直接删行**（写台账、可 Ctrl+Z），不弹确认框；
   - 双击或直接打字覆盖单元格，Enter 往下 / Tab 往右 / 方向键移动 / Esc 取消；
   - Ctrl+C 复制选中块、Ctrl+V 把 Excel 复制的 TSV 块粘进表格（空单元格保留原值）；
   - 「插入行」在选中行之后插入，点序用 `1.5` 这类小数，**原有仪器点序一个都不改**；
   - 「公式列 + 表达式」= Origin 的 Set Column Values：`x` 是本列原值、`i` 是行号、
     `Zp_ohm` 等列名可直接引用，支持 `+ - * / ( )` 与 `abs/sqrt/log/exp/sin/cos/min/max`。
     表达式用受限 AST 求值，**不用 eval**，写 `__import__('os')...` 会被拒。
2. **图上拖动数据点**：勾选工具栏「拖动数据点」，选「改 Y / 改 X / 改 X 与 Y」，
   按住点拖动，松手即写回并按生效坐标范围重算、重新导出核验。
3. **右栏「① 选中的点」**：改数值 / 写备注 / 排除 / 恢复 / 在工作表中定位。
   排除必须填理由，理由写进该行 `note` 与台账；不填会被后端直接拒绝。
4. **直接编辑** `datasets\<数据集ID>\working.csv`（UTF-8 BOM，七字段长表）；
   绘图只读它。`raw\` 是只读原始快照，永不改写。
   外部直接改 CSV 会被历史栈识别为一帧「外部直接编辑」，撤销仍能退回上一状态。

**撤销 / 重做**：顶部「↶ 撤销」「↷ 重做」，快捷键 Ctrl+Z / Ctrl+Y（或 Ctrl+Shift+Z）。
历史栈存在 `history\<数据集ID>.json`（不放进数据集目录，保持「每集固定三块」的契约），
最多 60 帧，**重启服务不丢**。撤销/重做先即时重绘，1.2 s 后自动补导出与核验。

**代码入口** `figlab.data.edit`（`set_value()` / `set_include()` / `set_note()`）与
`figlab.data.workbook`（`apply_ops()` / `undo()` / `redo()` / `workbook()`）；
比对用 `figlab.data.diff.compare()`，结果分四类：数值被改、参与标记翻转、新增行、丢失行。

## 四、改版式的入口

1. **网页右栏「③ 图层与标注」**：轴标题（X / Y）、加文字对象、逐条对象的字号与改字。
   这条是**图像层**的入口——图上能看到的东西都能在这里改。
2. **网页右栏「④ 导出」**：文件名（默认 `20261113阻抗作图`）、自动命名开关、格式。
   **格式默认只有 PDF，且 PDF 不可取消**；EPS / SVG / PNG 要自己勾。
   PNG 只作页内预览，不进交付物、不进归档。
3. **网页「⌄ 版式与算法」**（折叠）：样式、坐标范围、画布尺寸、等比例、圆拟合、截尾长度；
   应用后自动重新导出并重新核验。
4. **规格文件** `specs\<图ID>.json`：一张图全部版式；单图覆盖写进该文件 `overrides`
   字段，**不改预设**。
5. **三套预设** `figlab\spec\presets\`：
   - `inhouse`（默认）：8×6 cm、图层 20/10/70/70%、Times New Roman、刻度 9 / 标题 11 pt、
     四边框全画、刻度朝内、无网格、等比关闭（铺满）、无图例、末端同色单字母；
   - `generic`：Arial、8.5×6.5 cm、18/12/72/72%；
   - `dark_outline`：深色描边，适合 PPT。
   三套预设的 `export.formats` 都是 `["pdf"]`。
6. **多图窗口**：顶部「+ 新图」新建窗口，「删除当前图」删除。从项目树切换图窗口，两侧分界线的箭头可收起、展开侧栏。
7. **Origin 通道**：`figlab\origin\channel.py`，`ENABLED=False` 默认关闭。
   启用前用 `preflight()` 逐项核验图例位置、刻度方向、字号继承、导出目录。

**如实说明一处未消除的现象**：8 条曲线里有 3 对同材料平行重复，高频段物理重叠，

「该位置是否存在该曲线颜色」）8 条全部 100%，不属于整段被压住。拆线/点两层、按点数
排序绘制后该数字未改善，属数据本身重叠。要不要每类材料只取一条，属于实验取舍，
**由使用者裁决**，本平台不擅自替你定，也不删点。

## 六、已知缺陷清单逐条确认（§八）

1. matplotlib 3.11.2：字体类型只在 `render.engine.setup_rc()` 全局设
   `pdf.fonttype=42 / ps.fonttype=42 / svg.fonttype=none`，未使用 `savefig(pdf={...})`。
2. 所有契约路径经 `paths.absolute()`；`export.dir` 与 `data.working_csv` 在规格校验里
   强制绝对路径，`export_report.json` 记录 `export_dir_absolute=true`。
3. `run.py` 启动前 `port_free()` 预检；实测 8777 被旧 `scifig` 服务占用（PID 25976）
   判为 `False`，新平台改用 8778。
4. 符号白名单只有 `circle / square / triangle_up / triangle_down` 四种封闭实心形；
   `x / + / star / 开口符号` 在 `spec.schema.FORBIDDEN_MARKERS` 里被校验拒绝。
5. 去重按文件名主干，不用频率值取整；实测浮点差 1.03125 Hz，取整会失效。
6. 标注用 `annotation_rect_data()` 换算成数据坐标矩形去撞数据点，
   `verify_report.json` 记录每个标注的 `collides_with_points`（当前全 0），不数像素。
7. `raw\` 置只读且 `diff` 四类计数全 0；`fit_arc` 默认关，开启时强制
   `fit_disclaimer` 且在图上写 "Dashed arc: circle fit (reference, not measured)"；
   长表只含仪器测得的 Freq / Z' / Z''，派生 |Z|、Phase 不进表。

## 七、尚未实现的能力

- CHI 二进制导出解析：7 个只有 .bin 的测量仅登记哈希与点数，未纳入绘图；
  若要把它们画进来，需另写 `.bin` 数值解析器并补台账理由。
- 其他谱型处理层：光热只做导入容忍回归，未接绘图；CV/LSV/DPV/FSV（含双频欧姆压降
  补偿）、LF-NMR T2 反演、紫外可见/荧光、ECL 均未实现。范式接口在 `process/base.py`。
- 等效电路 / Randles-CPE 拟合：本机无 scipy，当前只有代数最小二乘参考圆拟合。
- 撤销栈是「整帧快照」而不是逐操作逆运算：单帧含整份工作副本，最多 60 帧；
  数据量再大时需换增量 diff 存储。
- 看图核验（视觉代理量化项已全部保留，未接入模型看图）。
- PPT 里「双击图回到平台」：现在靠图片超链接（放映单击 / 编辑 Ctrl+单击走通），
  真正意义上的双击需要把图做成 OLE 嵌入对象并配 Office 加载项，未做（见 9.3 末尾说明）。
- 需求单已按用户要求从界面移除（第三轮），只剩 `python -m figlab.tasks` 命令行留痕；
  想做算法类改动，直接在对话框里说，由 AI 改规格，界面不摆黑箱按钮。
- Origin 通道只保留 `preflight()` 与单位换算，未自动建表建图、不自动开窗。
- 组内共享目录的自动同步与冲突处理。
- 成品保留策略：同一个数据永远落**同一个**文件夹，重复导出覆盖同名文件，不堆版本。
  想留历史版本就自己复制一份改个名。迁移前按导出日期分级的旧产物已收进
  `桌面\FigLab\_旧归档\`，程序不再往里写。

### 8.5 图层编辑：拖标注、改名字、加文字

  松手即写入规格并重导出重核验。标注落点会被夹在图框内，避免核验判「越框」。
- **改名**：双击标注 → 就地输入框，Enter 提交、Esc 取消。单字母可以改成

- **复位**：列表里标「复位」的条目表示位置被拖过并锁定；点一下回到自动避让。
- 曲线列表里双击曲线名可改显示名（只影响列表，不动数据与图上标注）。

> 曲线本身不能拖：曲线的位置由实测数据决定，把整条线拖动等于改实验数值。
> 要整体平移数值用「公式填充」`x+Δ`（会写台账、可撤销），不要靠拖图伪装。

## 十、曲线平移 / Excel 式表格 / 跟手（2026-11-13 第三轮）

### 10.1 整条曲线平移：像 Origin 那样直接拖

顶栏 `⇄ 移线`（`?move=1` 可直达）打开后，按住任意曲线上下左右拖：

- 位移只写进规格 `series.off_x / off_y`（数据坐标单位），**工作副本一行都不动**，
  台账里不会出现「整体平移」这种假改动；点面板上会同时显示「图上值」和「实测值」。
- 拖动时轴范围按**未平移**的点算（`lock_axis`），所以刻度不会跟着跳、线跟手；
  松手后再按含平移的范围重算一次，曲线不会被切在图外。
- 曲线列表出现红色 `Δ0.00,18.00` 徽标，点 `↺` 归零。
- 曲线被拖出图框时，该曲线末端标注自动隐藏（不再画一个贴边的字母误导人），
  核验的「标注不压点 / 不越框」两项仍然成立。
- 导出报告与 `points.json` 里新增 `display_offsets`，PDF 上哪条线被平移过、移了多少，
  白纸黑字可查——**图上位置 ≠ 实测值这件事必须留痕**。

### 10.3 为什么以前「点了没反应」，现在怎么改的

三个原因，逐个修掉：

1. **一把大锁锁住整台服务**：以前 `do_GET/do_POST` 全在 `RENDER_LOCK` 里，
   一次导出约 0.9 s，这期间连 `ui.html`、缩略图、项目树都排队 → 点按钮像死机。
   现在只有真正碰 matplotlib 的接口排队（`HEAVY_GET / HEAVY_POST` 白名单）。
2. **每次点击都跑全量导出**：改一个勾选也要 PDF + 600 dpi PNG + 核验 + 归档。
   现在交互改动走 `fast=1`：只渲染 SVG，实测 **36–40 ms**；停手 1.2 s 后
   自动补一次全量导出（实测 720–900 ms），期间拖动会主动推迟，不抢 CPU。
3. **每次改完又重拉一次图**：`applyRender` 以前拿完结果还要再 `GET /api/figure`
   （等于多渲染一遍）。现在接口直接把 `spec/svg/points` 一起回传，省掉一半往返。

按钮统一加了 `busy` 状态与即时提示，所有请求都在 `try/finally` 里，出错会把原因写到顶栏。

## 十一、框选删点 / 剔除处断线（2026-11-13 第四轮）

### 11.1 怎么用（三步）

1. 点图区工具栏 `▭ 框选删点`（`?box=1` 可直达），或者按住 **Shift 直接在图上拖**（临时框选，不改模式）。
2. 按住鼠标拉一个矩形 → 框里的点全部被**红圈**圈中，底部弹出操作条：
   `框选 36 点　ITO 1-1 24 · ITO 2-2 12`。
3. 选一个动作：

| 动作 | 快捷键 | 结果 |
|---|---|---|
| **不画这些点** | `Delete` 或 `⏎` | 只从图上剔除（`include=0`），**数据保留**，曲线在剔除处**断开**；工作表里点「恢复」或 Ctrl+Z 可回来 |
| **彻底删行** | `Shift+Delete` | 从工作副本里真删掉这些行，行没了 → 两侧点直接相连（不留断点）；Ctrl+Z 可撤销 |
| 取消 | `Esc` | 清空选择，什么都不改 |

### 11.2 剔除处必须断线（这一轮最关键的判断）

以前的做法是「把参与点连成一条线」。框选删掉中段以后，两侧端点会被一条直线连接起来——
**那一段从没测过，图上却画出来了**，这是核验最忌讳的假数据。
所以现在按被剔除点的位置把曲线切段：`render/engine.py·split_runs()`，
有几个连续段就画几条线，符号仍是全部参与点。

- 分段数回到前端（`segments`），曲线列表显示红色 `2段` 徽标；
- 写进 `points.json` 的 `segments` / `segment_note`、`geometry.json` 的 `n_segments`，
  PDF 上哪条线断过、断成几段，白纸黑字可查；
- 版式里留了一个开关「剔除处断线」（`style.break_gaps`，默认开）。关掉就退回
  老行为（整条连续线），但**默认必须是断的**——不能默认画一条没测过的线。

### 11.3 顺带的行为一致

- 框选与 `拖点` / `移线` / `图层` 互斥：开一个自动关掉另一个，免得抢鼠标。
- 框选时 `#hotlayer` 关闭指针事件，所以框穿过数据点也不会被点的悬停拦住。
- 剔除理由：操作条里可填，留空默认写「框选剔除」，与「排除必须写理由」的规范一致；
  理由会进该行备注与台账（`subtype=workbook_exclude`）。
- 提交后工作表自动切到点数最多的那条曲线并选中这些行，删了什么一眼能对上。

## 十二、一键切换散点 / 折线 / 平滑（2026-11-13 第五轮）

### 12.1 怎么用

图区工具栏 **`连线 折线`**，点一下切下一个，三态循环：

| 状态 | 图上长什么样 | 适合什么场合 |
|---|---|---|
| **散点** | 只有符号，一条线都没有 | 文献里 Nyquist 的标准画法：只看实测点，不替读者猜走向 |
| **折线**（默认） | 相邻实测点直连 | 想让读者一眼看出趋势，且不想让曲线看起来"太拟合" |
| **平滑** | 过每个实测点的光滑曲线 | 想让图更像"拟合曲线"（组会、汇报、投稿里最常见的样子） |

版式面板底部也有下拉「连线画法」，要精确指定时用它。地址加 `?connect=scatter|segment|smooth`
可直达。

**三种画法一个数据点都不改**：点数、坐标、段数（框选剔除留下的断口）、热区位置全都一样，
只有"线怎么连"变了。所以可以随手来回切，切完 Ctrl+Z 里也不会多出一堆"假改动"。

### 12.2 为什么默认是折线，而不是平滑

三种画法的"诚实度"不一样：

- **散点**最保守——看到的每个点都是测出来的；
- **折线**每两点的中间也是直线近似，等于默认"两点之间线性变化"，但至少每段端点都是实测；
- **平滑**中间点是 **插值算出来的**，不是实测。它好看，但确实"造了"图上没有的数。

所以默认停在折线（和以前的画法一致，老规格没有这个键时也按折线走），
平滑必须由用户显式点出来，并且**在留痕里写明**：

```
points.json        connect / connect_note / line_vertices / interpolated
geometry.json      connect / curves.*.n_line_pts
export_report.json connect / connect_note
```

`interpolated: true` 就是"这条线的中间点不是测的"。以后有人拿着图问"这条曲线怎么拟合的"，
能一眼查到它其实是插值。

### 12.3 平滑怎么做的（没有 scipy 也能做）

`render/curve.py·smooth_path()`，单调三次 Hermite 插值（Fritsch–Carlson，就是 scipy 的 PCHIP）：

- **按点序参数化**（t = 0,1,2,…）而不是按横坐标排序。Nyquist 曲线在感抗尾巴上 Z' 会回折，
  按横坐标排会把回折处压平；按点序（频率序）走就不会。x、y 两分量各自插值，所以不要求 x 单调。
- **保形**：异号或为 0 的相邻斜率一律把导数置 0，所以不会在两点之间凭空鼓出一个峰
  （普通三次样条的经典毛病）。
- 每段加密约 10 个点，总顶点数上限 1600，避免 SVG 里堆几万个坐标。
- 少于 3 点没有弧度可插，原样返回。

自检结果：半圆 8 等分，折线中点偏离真圆 0.0192 → 平滑后 0.0052，且 9 个实测点全在曲线上。

**平滑不跨断点**：它按 `runs` 一段一段做。框选剔除留下的缺口仍然是缺口，不会被平滑"补上"。

### 12.4 顺手修的"点了没反应"

切画法要走一次重渲染，而重渲染和后台导出共用一把锁，连点时后面的点击会排在导出后面，
表现出来就是"点了不动"。现在按钮改成**乐观更新 + 串行队列**：

- 点下去立刻改按钮文案和下拉值（不等服务器）；
- 请求一发在路上时，再点只更新"目标值"，回来后再补发最后一次；
- 落定后以服务端真实状态为准。

所以连点三下会稳稳停在第三档，不会错乱。

## 十三、锁定一条曲线再框选（2026-11-14）

线一多，拉一个框会同时圈中相邻三四个条线的点。这一轮给框选加了"作用范围"：
**先锁定一条线，框选就只选它的点**。

### 13.1 三种锁定方式（都通往同一个状态 `S.aim`）

| 入口 | 操作 | 适合 |
|---|---|---|
| **图上单击** | 框选模式下，在某条线上点一下（不拖）＝锁定它；点空白＝解除 | 线分得开、一点就中 |
| **操作条下拉** | 图框上方那一条里的下拉，选一条曲线 | 线重叠、点不准（最稳） |
| **曲线列表** | 左侧「曲线」里点某一行（左边缘出现蓝色竖条＝已锁定） | 按名字挑，最不容易错 |

锁定后：其他曲线在图上**淡出到 14%**，锁定的那条保持原色；曲线名下拉用该曲线的颜色描边，
后面还标着"这条线被框到几个点"。`Esc` 分两级——先清框选，再解除锁定。

### 13.2 淡出怎么做到的（gid）

matplotlib 画的线在 SVG 里没有名字，页面没法单独指着某一条。所以渲染时给每条曲线打了 id：

```
cv0-line-0   第 0 条曲线的第 0 段连线
cv0-line-1   断线后的第 1 段（剔除中段时出现）
cv0-mk       第 0 条曲线的全部符号
```

页面靠 `curve_gids`（曲线名 → 序号）找到对应 `<g>`，改它的 `opacity`。
**断线时必须每一段都有 id**，否则后半截淡不掉、看着还在却选不中——第十二层专门验这条。
散点模式本来就没有线，所以只有 `-mk`；gid 只是 SVG 元数据，PDF 导出不受影响。

### 13.3 框完才发现框多了？不用重拉

框完以后下拉里每条线后面会带"（N）"，是**这个框里**它有几个点。
`全部曲线（177）` → `e · Bi2S3+MnO2@PtAu 1-1（31）`，换个选项就按新范围重算选择，
不用重新拉框。三种锁定方式随便切，选择范围永远是"当前这个框 ∩ 当前锁定曲线"。

### 13.4 顺手修了一条自相矛盾的验收口径

`acceptance.py §八.7` 原来要求 diff 四类全为 0，其中包括 `include_flipped`——
可"框选删点"本来就是要把 `include` 从 1 改成 0 的功能。等于产品允许删点、验收不许删点。
（这轮就撞上了：图上真实被剔的 8 个点让验收从 7/7 掉到 6/7。）

现在口径改为：**实测数值、增行、丢行必须 0；剔除允许存在，但每一行都必须写了理由**
（`exclusions_without_reason` 必须为空）。既不放宽数值改动的红线，也不再惩罚正当的删点。

### 14.1 为什么导出会和界面不一样

导出接口原来只认 `figure` 这个 id，自己去磁盘 `load_spec()`。于是出现两条各说各话的路径：

```
页面：点了「散点」→ 前端 S.spec.style.connect = scatter（屏幕上立刻变）
导出：读磁盘 specs/<id>.json → 还是 segment → PPT 里就是折线
```

只要有一次改动没写进磁盘（连点太快、两个标签页各持一份、切换后马上点 PPT），
两边就分家了，而且图上完全看不出来。

**改法：导出以页面那份规格为准。** 页面把当前 `S.spec` 整份 POST 上来，
后端先校验、再落盘、再用这份渲染，绝不再回磁盘读旧值。
`/api/export` 与 `/api/pptx` 都走这条路。

验证方式是硬证据，不是"看起来对"：matplotlib 的 PNG 输出是确定性的
（同一规格两次渲染逐字节相同），所以直接把 **PPT 里嵌的那张 PNG** 取出来，
和「按当前规格渲染的散点图」做字节比对——相等即证明它确实是散点那一版。

### 14.6 同一个数据只留一个名字（按数据日期定名，定完不改）

用户第二天的反馈，配了一张桌面截图：`FigLab输出\2026-11-13` 和 `2026-11-14` 两个文件夹，
里面是同一批 `eis_20261107` 的图。原话：「你怎么同一个数据，两天都有不同的保存，
只要按原始文件的日期命名之后不改就行了」。

根因不在文件夹，在**命名日期取的是导出当天**：

```python
default_base(...)  # 旧：datetime.now().strftime("%Y%m%d")
resolve_name(...)  # 旧：每次打开/导出都重算 → 11-13 导叫 20261113阻抗作图，
                   #     11-14 再导叫 20261114阻抗作图 → 两个文件夹
```

**新口径：日期取数据自己的，写进 `export.name_date` 之后冻结。**

```python
data_date("eis_20261107") == "20261107"     # 数据集名里的日期优先
# 没有日期就退到 原始快照/源文件的最早修改日 → 数据集目录日 → 今天（仅兜底）
```

| 场景 | 以前 | 现在 |
|---|---|---|
| 11-13 首次导出 | `20261113阻抗作图` | `20261107阻抗作图` |
| 11-14 再导出 | `20261114阻抗作图`（新文件夹） | `20261107阻抗作图`（同名覆盖，还是那个文件夹） |
| 隔一个月打开项目 | 名字跟着当天变 | 一个字都不变 |
| 用户手动改过名（`auto_name=false`） | 不动 | 不动 |

配套动作：

- `resolve_name()` 第一次算完就把 `name_date` 写进规格，之后只复用它；日期永不漂移。

- 桌面 `FigLab输出\` 已整体收进 `桌面\FigLab\_旧归档\`（89 个文件一个没删，结构不变），
  桌面根目录不再有两个输出文件夹。
- `scripts/migrate_name_date.py` 是一次性迁移脚本：把已有规格与桌面成品夹的名字从
  导出日改成数据日（先跑预览，加 `--apply` 才动文件）。

以及"同一份数据隔两天再导名字一个字都不变"。

  要连原始数据一起搬，得连 `datasets/<名字>/raw/` 一起拷。核验用的对比仍以本机原始快照为准。

## 十五、选线：单击图上任意一条线就选中它（2026-11-14）

用户提的是「增加一个选线的功能」。

在此之前，"锁定一条曲线"这件事是**藏在框选里的**：必须先点「框选删点」进入框选模式，
再单击某条线才算锁定；不框选的时候点线没有任何反应，其它曲线也不会淡出。线一多，
想看清某一条、或者想单独看它，得先去左侧列表里找到那一行。

**现在的口径：任何时候单击图上任意一条线（点在它的数据点上也算），就选中它。**

| 操作 | 结果 |
|---|---|
| 单击一条线 / 点它的某个数据点 | 选中它：这条线加粗、其余淡到 0.14、左侧列表对应行高亮 |
| 再点一次同一条 / 点图区空白 / `Esc` | 取消选中 |
| 右上角选中条 | 彩色圆点 + 曲线名 + 点数 + 「只看这条」「表」「×」 |
| 「只看这条」 | 除它以外的曲线隐藏（写 `include`），按钮变「恢复全部」，点了按操作前的快照还原 |
| 「表」 | 数据表跳到这条曲线的工作副本 |

### 15.1 一条硬规矩：选中不许改图

选中是**纯显示层**：只改 SVG 的 `opacity` 与 `stroke-width`，不写规格、不触发导出、
不碰数据。所以可以放心点来点去，桌面上不会多出文件，图上也不会留下痕迹。
唯一会写规格的是「只看这条」——因为界面隐藏了曲线，导出的图也必须跟着隐藏，
否则又违背"所见即所得"。它记了操作前的显隐快照，「恢复全部」原样还原。

### 15.2 三个当场踩到的坑

1. **点在数据点上选不中**。数据点被 `.hot` 热区盖着，`onHotDown()` 里有
   `e.stopPropagation()`，`viewport` 的 `mousedown` 根本不触发，选线的起点就丢了。
   改法：在 `onHotDown` 里也记一次 `S.click0`，`mouseup` 再按 `dataset.i` 反查曲线。
2. **选中条放底部会压住 X 轴标题**。第一版放 `bottom:8px`，截图一看 `Z'(Ω)` 被挡了一半，
   挪到右上角。
3. **切图后旧选中残留**。`S.aim` 还指着上一张图的曲线名，`paintAim()` 找不到它的
   `curveGids`，于是**所有**曲线都被判成"非目标"、整张图淡成一片。两处兜底：
   `loadFigure()` 里清空，`paintAim()` 里再校验一次曲线名还在不在。

### 15.3 和框选的关系

选中只是"范围"，框选才删点。选中之后开「框选删点」，拉框只作用于这一条——
这正是原来"线多时只删一条"的用法，只是现在不必先进框选模式才能选线。
三种入口（图上单击 / 操作条下拉 / 左侧列表点一行）改的是同一个 `S.aim`，状态永远一致。

### 15.4 验收

新增 `tests/layer14_select.mjs`（CDP 真浏览器真点，**29 项**）：

| 组 | 验的事 |
|---|---|
| [2] | 普通模式单击 → 点中哪条选中哪条、选中条弹出并显示名字/点数、其它线淡出、本线保持亮度、列表只高亮一行 |
| [3] | 再点同一条取消、点空白取消 |
| [4] | 「只看这条」只留 1 条参与绘制、按钮变「恢复全部」、点回来按原样还原 |
| [5] | 「表」跳到这条曲线的工作副本 |
| [6] | 换一张图后选中自动清空、新图没有被整体淡出 |
| [7][8] | Esc 取消；收尾整份规格写回，显隐与开始时一致，控制台 0 报错 |

回归：`ui_smoke.mjs` 全过；第七层 59、第十一层 45、第十二层 26、第十三层 38 不变。

## 十六、选线按钮：先点「◎ 选线」，再点你要改的那条线（2026-11-14）

用户的要求很直白：「我是想要一个按钮，点了选线按钮后我就可以选择我想要的线去改动了」。

上一版是"随时单击曲线就选中"，能用，但有两个问题：**线细的时候点不定**（容差 16 px，
曲线中段常常点空），而且**点之前不知道自己会点到谁**（几条线挤在一起时尤其明显）。

### 16.1 现在的流程

```
点「◎ 选线」  →  鼠标在图区移动，最近的那条线立刻变粗、其余淡到 0.32，旁边报出
                 「单击选中「b · Bi2S3+HP-MnO2@PtAu+4-CD 1-1」 32 点」
              →  单击 → 选中（自动退出模式）→ 右上角选中条：「只看这条 / 删点 / 表 / ×」
```

- 模式里容差从 16 px 放宽到 **26 px**，曲线中段、细线、贴着别的线都好点。
- 进模式时自动关掉抢同一个点击的「框选删点」「移线」「拖点」，三种模式互斥。
- **选完自动退出模式**：接下来的拖动、框选、导出都还是原来的手感，不会因为忘了退模式而"点哪都选线"。
- `Esc` 退出模式；再按 `Esc` 取消选中。

### 16.2 选中之后能改什么

选中不是终点，是"改动的入口"。选中条上的三个动作都是针对这一条的：

| 按钮 | 作用 |
|---|---|
| 只看这条 | 其它曲线隐藏（写 `include`，导出跟着变），再点一次按原样还原 |
| **删点**（新） | 直接进框选模式，且框选下拉已经锁死这条线——拉个框只剔它的点，别的线一根不动 |
| 表 | 数据表跳到这条曲线的工作副本（改值/删行都在那儿） |

另外选中后双击左侧列表那行可改名，开「移线」拖动就是整条平移，开「拖点」可以逐点拖。

### 16.3 顺手修的两处

1. **框选模式下 Esc 会把人困住**。原来框选模式里按 Esc 只清点、不清模式，清完点之后
   再按 Esc 反而去解除了曲线锁定，人还在框选模式里出不来。现在分三层：
   清点 → 退出框选 → 解除选中，一层一退。
2. **冒烟测试自己漏了状态**。`ui_smoke.mjs` 第 3 节开「移线」拖完一次后没关，
   后面"单击曲线锁定"那步其实是被移线模式接管了（以前恰好靠框选模式的单击兜住）。
   现在拖完就关，并断言 `S.moveMode === false`。

### 16.4 验收

新增 `tests/layer15_pick.mjs`（CDP 真浏览器，**36 项**）：

| 组 | 验的事 |
|---|---|
| [1] | 按钮在、初始未激活、光标不是十字 |
| [2] | 点按钮才进模式：按钮点亮、`body.pickmode`、光标十字、状态栏给提示 |
| [3] | 离顶点 20 px 处：普通 16 px 门槛点不到、放宽到 26 px 才点到（证明不是"碰巧"）；高亮那条加粗 1.40×、其它 10 组淡到 0.32、气泡报名字与点数 |
| [4] | 单击 → 选中的正是刚才亮起来的那条、模式自动退出、选中条出现、气泡收起 |

| [7] | Esc 退出模式、悬停高亮清空 |

### 17.4 规格里的路径：一律相对项目根（2026-11-14 晚）

此前的写法是「层间契约一律绝对路径」，好处是自己机器上不会解析错，代价是**仓库不可移植**：
`specs/*.json` 里存的是带盘符的绝对路径（`D:\...\figlab\datasets\...`），别人克隆到 `~/code/figlab`
打开图就报「working_csv 不存在」。

现在的规矩（`figlab/paths.py`）：

| 字段 | 存什么 | 谁解析 |
|---|---|---|
| `data.working_csv` | `datasets/eis_20261107/working.csv`（相对项目根，正斜杠） | 读的时候 `paths.absolute()` |
| `export.dir` | `outputs/eis_wide`（相对项目根） | 同上 |
| 桌面成品目录 / 手填 PPT 路径 | 绝对路径（本就在项目外） | 原样使用 |

- `paths.portable(p)`：写规格前把项目内路径转相对，项目外的原样保留；跨盘符时退回绝对路径。
- `save_spec()` 统一做这一步，所以不论是建图、改版式、打开项目文件，落盘的都是相对写法。
- `paths.display_source(p)`：数据来源目录写成 `~/Desktop/...`，元数据进仓库不泄露用户名。
- `spec/schema.py` 的校验从「必须是绝对路径」改成「解析后必须存在」，相对写法照样能过。
- 打开别人给的项目文件（`.figlab`）时，规格里的旧路径全部作废，重新指向刚恢复的数据集。
- **实测**：整份项目拷到另一个目录启动 → 示例图渲染 185 点 / 6 条曲线、
  导出写进该副本自己的 `outputs`，成品落到当前用户桌面 —— 与源目录完全无关。
